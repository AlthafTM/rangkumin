# Artifact creation and visual quality

## Choose the requested format

Use PDF for a fixed study guide when requested; Word for editable reports; slides for presentation; PNG/JPG for a table image. Do not substitute PDF for Word or files for requested chat text. Keep full notes and cheatsheets separate when requested.

For a supplied template, inspect page size, margins, font, heading hierarchy, numbering, tables, cover, and logos before editing. Preserve the user's approved structure. Use only verified/provided identity details. Never invent a class, student ID, author, or institutional requirement.

Keep original files unchanged unless replacement is explicitly requested. Use a distinct descriptive output name and the requested destination. Do not include source documents or private identifiers in public examples or repositories.

## Typesetting

- Render mathematical notation properly, including large sigma bounds, fractions, powers, Greek letters, and subscripts. Raw LaTeX commands are not a finished PDF formula.
- Use a readable body size, strong contrast, moderate line spacing, and purposeful white space. Do not compress content by making it too small.
- Use real headings, lists, and editable tables in Word. Do not simulate spacing with repeated blank paragraphs or spaces.
- Keep code monospaced and indented. Prefer splitting at a function boundary to shrinking it or clipping long lines. Keep file labels and corresponding code together.
- Make table columns fit their content. Repeat headers across pages where supported; avoid orphan labels and fragmented short rows.
- Use captions only where they help identify a source, diagram, or example. Avoid decorative content that competes with the material.
- Preserve the exact relationships in diagrams; export them at a resolution/size that keeps all labels readable.

## Render, inspect, repair

1. Generate the requested artifact using available tools and any applicable host document/PDF/presentation workflow.
2. Verify the file exists and can be parsed/opened.
3. Render every final page or slide for visual inspection. A contact sheet helps coverage; inspect dense equations, tables, and diagrams at readable resolution.
4. Check for missing glyphs, clipping, overlaps, overflow, broken line wraps, page-number mistakes, excessive blank areas, and inconsistent spacing. Recheck altered pages after repairs.
5. Compare extracted final text against the content plan: required questions, formulas, answer letters, block labels, and conclusions must survive export.
6. Recheck logical correctness separately. A neat page does not verify its mathematics.

If rendering or the requested format is unavailable, state that specific limitation. Offer a usable alternative without claiming it meets the unavailable check. Never mark visual QA complete because a file merely saved successfully.

## Delivery and revision

Provide a concise link to the actual artifact and only necessary notes. Do not narrate all tool operations. For revisions, update the intended artifact and cross-references without removing unrelated approved sections. Claim only checks performed. Sending to a contact, publishing, or replacing originals requires authorization for that specific action; do not infer it from file creation.
